# 交接班小组件设计

## 目标

在 NetBox 首页新增一个名称为“交接班”的 `2×2` 小组件。用户可选择班次开始时间，也可通过快捷箭头在每日 09:00 与 18:00 两个班次点之间切换。点击“生成交接班内容”后，系统按点击时的最新数据生成六章交接文本，在弹窗中预览并复制。

本功能不新增数据库模型，不生成迁移。

## 小组件交互

### 班次开始时间

- 当前本地时间为 00:00–11:59 时，默认值为昨日 18:00。
- 当前本地时间为 12:00–23:59 时，默认值为当日 09:00。
- 时间控件允许手工选择任意日期和时间。
- 时间控件右侧提供上下箭头，不再额外显示重复的文字说明：
  - 向上箭头：选择前一个班次点。
  - 向下箭头：选择后一个班次点。
- 班次点按 `…… → 昨日 18:00 → 今日 09:00 → 今日 18:00 → 明日 09:00 → ……` 连续排列。
- 手工选择非 09:00/18:00 的时间后，向上选择严格早于该时间的最近班次点，向下选择严格晚于该时间的最近班次点。

### 生成与弹窗

- 首页仅显示班次时间控件、快捷箭头和“生成交接班内容”按钮。
- 点击按钮时才向插件专用后端视图请求内容，确保“截至时间”和业务数据以点击时为准。
- 请求期间按钮进入加载状态并禁止重复点击。
- 成功后打开“交接班内容”弹窗，正文以保留换行的纯文本区域展示。
- 弹窗底部按钮从左到右为“复制内容”“关闭”。
- 复制按钮复用“今明割接”小组件的 MDI 图标：默认显示 `mdi-content-copy` 与“复制内容”，复制成功后显示 `mdi-check` 与“已复制”，约 1.5 秒后恢复默认图标和文案。
- 复制时优先使用 Clipboard API；API 不可用或写入被拒绝时，自动使用隐藏文本框回退复制。两种方式均失败时短时显示“复制失败”，随后同样恢复默认图标和文案。
- 生成失败或班次参数不合法时，小组件显示可读错误提示，不打开空弹窗。

## 架构与数据流

### 组件边界

- Dashboard widget 负责渲染小组件外壳、默认班次时间和生成入口。
- 前端脚本负责手工时间输入、上下班次切换、调用生成视图、弹窗展示和复制反馈。
- 独立的交接班服务模块负责查询结果到纯文本所需结构的转换及文本格式化。
- 插件内新增专用只读生成视图，接收班次开始时间，使用服务器当前本地时间生成内容并返回 JSON。

### 权限与时间

- 生成视图使用当前请求用户；接班人优先显示用户全名，无全名时回退到用户名。
- 故障、割接和重保查询均使用 NetBox queryset 的 `restrict(request.user, 'view')` 限制对象权限。
- 班次开始时间由请求参数传入，解析后转换为当前 Django 时区的 aware datetime。
- “截至时间”为后端处理请求时的服务器本地时间，不采用页面加载时间或浏览器时间。
- 今明窗口起点为“截至时间”，终点为截至日期次日之后的 00:00，即文案中的“次日 24:00”。

## 数据口径

### 一、故障移交（不含挂起）

- 只统计 `fault_status='processing'` 的故障。
- 排除 `is_suspended=True` 的故障；状态本身为挂起的记录也不属于 `processing`，因此不会进入结果。
- 故障起始时间大于或等于班次开始时间的，计入“本班新增故障”。
- 故障起始时间早于班次开始时间的，计入“历史遗留故障”。
- 两类故障使用同一批权限受限的待处理故障数据，避免章节一计数与章节二明细不一致。
- 计数文案固定为“本班移交待处理故障X起，另有前期班次移交需接续处理故障X起。（请在信息系统核对清点）”，不在数字后附加“当班新增故障，正在处理”或“非本班次故障即历史遗留”等解释文字。

### 二、补充说明（值班留言）

- 对章节一中的全部待处理故障逐条生成说明，按故障起始时间、主键稳定排序。
- 一级原因使用 `get_interruption_reason_display()` 的显示值。
- 影响业务从故障关联的影响记录中汇总：裸纤使用裸纤业务名称；电路优先使用专线名称，无专线名称时使用电路名称。多个名称去重后以 `、` 分隔。
- 故障有关联业务名称时显示 `影响：业务名称线路`；没有关联业务或关联业务名称均为空时显示 `影响：线路组网`，不得显示 `影响：-线路`。
- 故障处理人使用 `handler`。
- 处理进度不读取日志。按故障处理时间线的阶段顺序，选择最后一个已有时间的阶段，并输出该阶段的本地时间和阶段名称。
- 时间线阶段顺序为：故障起始、处理派发、维修出发、到达现场、故障恢复；光纤类故障末尾再包含封包完成时间。
- 处理进度格式为 `YYYY年M月D日HH:mm:ss阶段名称`。

### 空格规范

- 从数据库提取的文字字段统一删除横向空白字符，包括业务名称、故障编号、原因、处理人、阶段名称、割接字段、重保/通知标题及描述；保留换行。
- 所有日期时间统一紧凑显示为 `YYYY年M月D日HH:mm:ss`，日期与时刻之间不留空格；处理进度的时间与阶段名称之间也不留空格。
- 接班人首行保留固定排版空格，格式为 `接班人: 李四    截至2026年8月4日15:51:50`。
- 手机交接行保留固定排版空格，仍为 `数量:  2        完好性: 正常  有损坏`。
- 不对最终全文执行全局去空格，避免破坏上述固定排版。

### 三、今明割接任务

- 仅纳入状态为“待实施”的割接任务。
- 计划割接时间范围为 `[截至时间, 次日24:00)`。
- 只要割接关联任一裸纤影响业务，即归入“（一）影响裸纤业务”；即使同时影响电路，也不在第二组重复生成。
- 没有关联裸纤影响业务的割接归入“（二）仅影响电路业务”，包括仅关联电路以及尚未关联任何影响业务的割接。
- 尚未关联业务的割接不额外生成“未关联”提示。
- 裸纤组的“影响业务”汇总该割接关联的裸纤业务名称并去重；电路组保持需求模板，不增加“影响业务”行。
- Z 端存在多个站点时，以 `、` 分隔。
- 预计影响时长使用 `planned_impact_minutes` 并显示为分钟。

### 四、重保事项与五、重要通知

- 查询窗口包含当前仍在生效的记录，以及从截至时间至次日 24:00 前开始的记录。
- 已在截至时间前结束的记录不生成。
- “重保事项”使用 `HeavyDuty.type='important'`。
- “重要通知”使用 `HeavyDuty.type='notice'`。
- 两章均按开始时间、主键稳定排序，输出开始时间、结束时间、标题和描述/通知。
- `HeavyDuty.type='memo'` 不在本次交接文本中单独查询；章节二由待处理故障明细组成。

### 六、手机交接

保持固定内容：

```text
六、手机交接
数量:  2        完好性: 正常  有损坏
```

## 文本规则

- 生成文本严格保留需求定义的一至六章和各级编号。
- 第一行使用实际值，格式为 `接班人: 用户显示名    截至YYYY年M月D日HH:mm:ss`。
- 章节三标题中的终点显示为 `至YYYY年M月D日24:00`。
- 有多条数据时使用连续的中文全角编号 `（1）`、`（2）`。
- 任何无数据章节保留标题，并在下一行输出 `无`。
- 单个字段为空时统一显示 `-`。
- 动态文本保留用户录入内容，去除首尾空白；业务名称和站点名称在聚合时去重。

## 查询与性能

- 待处理故障查询预取故障影响、裸纤业务和电路业务，避免逐条查询影响业务。
- 交接班服务仅访问生成文本实际需要的字段和关联对象。
- 割接查询预取 A/Z 端站点及影响业务；同一割接只在一个业务分类中输出一次。
- 重保与通知在一个时间窗口查询中按类型拆分。
- 所有查询都在一次点击请求中完成，不由浏览器串联调用现有 REST API。

## 错误处理

- 缺少班次参数、日期格式非法或无法转换到当前时区时，返回 400 和可读错误信息。
- 未认证请求不生成数据，交由 NetBox 登录机制处理。
- 生成阶段发生未预期异常时记录服务器日志，并向前端返回通用失败提示，不回显堆栈或敏感信息。
- Clipboard API 不可用或被拒绝时自动尝试隐藏文本框回退复制；仅当回退方式也失败时，按钮短时显示“复制失败”，弹窗正文保持可手工选择。

## 测试设计

- 默认班次：验证上午默认昨日 18:00、下午默认当日 09:00，以及 12:00 分界。
- 快捷箭头：验证 09:00/18:00 同日切换、跨日切换，以及非班次点手工时间向前/向后取最近班次点。
- 故障：验证本班新增与历史遗留计数、处理状态、挂起排除、对象权限、影响业务去重和缺失字段 `-`。
- 时间线：验证每个阶段作为最后已填阶段时的时间与名称，及光纤类封包完成阶段。
- 割接：验证截至时间下界、次日 24:00 上界、待实施状态、裸纤优先分组、电路分组和无影响业务分组。
- 重保/通知：验证当前生效、未来开始、已结束排除、类型拆分和窗口上界。
- 格式化：验证完整六章、连续编号、空章节“无”、固定手机交接和中文时间格式。
- 视图与模板：验证登录用户显示、JSON 成功/错误响应、加载态、弹窗按钮顺序、默认复制图标、复制成功图标、Clipboard API 安全上下文判断、复制拒绝后的回退路径及“已复制/复制失败”反馈。
- 项目无 NetBox 运行环境；以纯函数单元测试、源码级回归测试、Python 编译检查和浏览器人工验证为验收手段。

## 不在范围内

- 不保存交接班历史记录。
- 不记录手机实际完好性，也不增加手机状态输入控件。
- 不发送消息、邮件或外部通知。
- 不修改 NetBox 核心目录或创建新的 API 端点假设；只增加本插件明确注册的生成视图。
