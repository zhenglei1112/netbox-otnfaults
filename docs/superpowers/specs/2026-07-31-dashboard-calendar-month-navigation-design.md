# 仪表盘日历小组件月份滚动设计

## 目标

为故障月历和割接月历小组件增加相互独立的月份滚动能力。用户点击左右侧箭头后，仅刷新被操作的小组件，不刷新整个仪表盘。

## 交互设计

- 两个小组件首次加载时仍显示当前月。
- 每个小组件在内容区域左、右两侧的垂直中点提供月份滚动热区。
- 箭头平时透明不可见；鼠标进入对应热区、按钮获得键盘焦点时显示。
- 左箭头切换到上一月，历史月份不设下限。
- 故障月历最多切换到当前月。
- 割接月历最多切换到当前日期所在月的下个月。
- 到达各自上限后，右箭头保持不可用且不可见。
- 请求进行期间临时禁用当前小组件的两个箭头，防止重复请求。
- 请求失败时保留当前月份内容，并恢复箭头状态。
- 今日标记仅在显示月份包含当前日期时出现。

## 架构

采用两个只读局部刷新端点，分别负责故障月历和割接月历。端点复用现有 Widget 的权限过滤与模板渲染逻辑，返回可直接替换的小组件 HTML 片段。

后端增加共用月份工具函数，负责：

1. 从请求参数解析 `year`、`month`。
2. 对非法参数回退到当前月。
3. 对超过小组件上限的月份收敛到允许的最晚月份。
4. 计算上一月、下一月及跨年边界。

两个 Widget 的 `render()` 方法读取各自请求中的目标年月，并把局部刷新 URL、上一月参数、下一月参数和能否向后滚动传给模板。故障与割接使用独立端点，因此操作一个小组件不会改变另一个小组件的状态。

## 前端数据流

1. 用户将鼠标移到小组件左侧或右侧中部热区，箭头淡入显示。
2. 用户点击可用箭头。
3. 共用的事件委托脚本从按钮读取局部刷新 URL。
4. 脚本通过 `fetch()` 发起同源 GET 请求。
5. 请求成功后，用返回的 HTML 替换当前小组件根节点。
6. 全局事件委托继续作用于新片段，无需重复注册监听器。

脚本只处理带专用数据属性的日历导航按钮，不拦截日期单元格原有的故障或割接列表跳转。

## 后端与权限

- 故障端点继续使用 `OtnFault.objects.restrict(request.user, 'view')`。
- 割接端点继续使用 `CutoverTask.objects.restrict(request.user, 'view')`。
- 两个端点均要求登录，并仅响应 GET。
- 不新增或猜测 NetBox 核心 API；路由全部位于本插件命名空间。
- 月份限制在后端再次校验，不能通过手工修改 URL 查看未来禁用月份。

## 错误处理

- 非数字年份、月份或不在 `1..12` 范围内的月份回退到当前月。
- 超过允许上限的年月收敛到该小组件的最晚月份。
- 局部请求返回非成功状态或网络失败时，前端不替换现有内容。
- 快速重复点击通过请求期禁用避免并发覆盖。

## 测试策略

- 为共用月份工具增加单元测试，覆盖正常月份、非法输入、前后月跨年和未来上限收敛。
- 为故障月历增加测试，锁定其未来上限为当前月。
- 为割接月历增加测试，锁定其未来上限为下个月并覆盖十二月至次年一月。
- 为两个局部端点增加源码级或可运行视图测试，确认路由、登录限制和对应 Widget 渲染。
- 为模板增加源码级回归测试，确认左右热区、默认隐藏、悬停/焦点显示、不可用状态及 `fetch()` 局部替换。
- 运行两个现有日历测试文件、相关 URL/视图测试和 Python 编译检查。

## 范围外事项

- 不保存用户最后浏览的月份。
- 不修改日期单元格跳转行为。
- 不增加触摸滑动手势或键盘左右方向键切月。
- 不修改 NetBox 核心目录、仪表盘布局或其他小组件。
