# 态势大屏新版：第一阶段外壳设计

## 目标

在不修改现有态势大屏的前提下，新增可并行访问的新版态势大屏入口。第一阶段只建立新版页面的视觉骨架和 MapLibre 底图，为后续按功能逐步迁移或重新实现提供隔离边界。

## 范围

本阶段包括：

- 新增独立的新版大屏路由和菜单入口。
- 新增独立 view、模板、CSS 和 JavaScript 文件。
- 复用现有深色科技视觉语言、字体、顶部标题和时间显示样式。
- 主区域使用左侧信息区、右侧地图区的布局。
- 右侧初始化 MapLibre 底图，但不加载任何业务数据或业务图层。
- 为底图配置缺失或加载失败提供页面内错误状态。

本阶段不包括：

- 修改、替换或删除现有 `/dashboard/` 页面、接口或静态资源。
- 复用旧大屏的 `DashboardDataAPI`、轮询、播控、事件队列、故障/割接/重保面板。
- 加载站点、线路、故障、割接、重保或热力图数据。
- 新增或修改数据库模型、迁移和 NetBox 核心文件。

## 路由和隔离

- 旧入口 `/dashboard/` 保持不变，作为稳定的旧版基线。
- 新入口为 `/dashboard-v2/`，菜单文本为“态势大屏（新版）”。
- 新版使用专属的 view、模板和静态资源命名；不得调用旧版的 `DashboardApp`、`Panels`、`DirectingEngine` 或 `MapEngine` 全局模块。
- 允许复用第三方静态库（MapLibre、PMTiles）及插件全局地图配置；新版自行维护其初始化逻辑和状态。

## 页面布局

页面延续现有深色配色、Rajdhani、JetBrains Mono 和 Noto Sans SC 字体，以及现有顶部标题文案和日期时间区域。

主区域采用 CSS Grid：

```css
grid-template-columns: clamp(360px, 31%, 780px) minmax(0, 1fr);
gap: 16px;
```

- 左栏为信息显示区，第一阶段只放置语义化空容器，不显示虚构业务指标。
- 右栏为地图区，MapLibre 地图画布填满容器。
- 常规屏幕下左栏约占31%，4K屏幕下封顶780px，超出的宽度自动分配给地图区。
- 小于可支持的最小宽度时，页面保持大屏固定展示定位，不承诺移动端适配。

## 地图初始化

- 新增专属地图初始化脚本，例如 `dashboard_v2/map_engine.js`。
- 读取插件既有的默认中心、缩放、俯仰角、本地 PMTiles 底图地址和字形地址配置。
- 第一阶段以原配置的 `local_tiles_url` 作为唯一底图来源；只要地址存在就初始化 PMTiles，不受旧版 `use_local_basemap` 开关影响。瓦片地址缺失时不创建空白地图，并明确显示配置错误。
- 底图风格保持当前新版大屏所使用的深色背景和 PMTiles 协议。
- 第一阶段不创建站点、路径、故障、割接、重保、热力图和播控图层。
- 保持大屏展示模式，禁用拖拽、滚轮缩放和其他常规地图交互。
- 配置缺失、MapLibre 初始化失败或地图 `error` 事件发生时，在地图容器内显示可读的错误提示；页面其他区域仍正常显示。

## 安全和质量约束

- 新版第一阶段不请求业务数据，因此不引入旧版 `innerHTML` 拼接业务字段的 XSS 风险。
- 配置对象通过 Django 的安全 JSON 序列化方式注入模板，避免通过字符串拼接注入 JavaScript。
- 不复用旧版30秒轮询，避免无业务功能时产生无效请求。
- 所有新增 Python 代码使用完整类型提示。

## 验收与测试

- 旧版 `/dashboard/` 的路由、模板、接口和静态文件不发生变更。
- 具备权限的用户能访问 `/dashboard-v2/`，并从插件菜单进入新版页面。
- 页面具有顶部标题、左信息区和右地图区；布局使用31/69比例与16px间距。
- 在具备有效地图配置时 MapLibre 完成底图初始化；在配置或加载异常时展示错误状态。
- 新版页面不调用旧版大屏业务数据接口，也不加载旧版业务 JS 模块。
- 新增测试覆盖路由、模板配置、布局约束和新版地图初始化脚本；执行相关测试与 JavaScript 语法检查。
- 使用 Node 行为测试实际执行地图模块，覆盖有效 PMTiles、旧开关关闭但地址有效、地址缺失、构造失败、运行时错误事件，以及 `error` 先于 `load` 的竞态。

## 后续增量原则

每次新增新版功能时，必须明确其来源：复用旧能力、调整旧能力，或全新实现。若复用旧能力，同时纳入已知问题的针对性修复，包括数据口径、XSS、接口性能、请求并发、事件优先级和可验证测试；不得直接复制旧模块后再积累技术债务。
