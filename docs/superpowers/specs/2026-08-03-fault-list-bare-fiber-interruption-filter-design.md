# 故障列表“造成裸纤业务中断”筛选设计

## 目标

在故障模型的列表筛选页面增加“造成裸纤业务中断”布尔筛选项。该筛选项位于“故障起始时间”之后、“处理派发时间”之前，用于筛选造成裸纤业务中断数量大于 0 或等于 0 的故障。

## 统计口径

沿用故障列表现有“裸纤业务中断数”的统计口径：故障直接关联的 `OtnFaultImpact` 同时满足以下条件时，计为一条裸纤业务中断影响记录：

- `service_type=bare_fiber`；
- `business_impact=interrupted`。

筛选“是”时返回至少存在一条上述影响记录的故障；筛选“否”时返回不存在上述影响记录的故障；未选择时不改变查询结果。多条匹配影响记录不得导致故障列表重复。

## 后端设计

在 `OtnFaultFilterSet` 增加布尔筛选字段和专用筛选方法。筛选方法直接通过 `impacts` 关联关系判断是否存在符合口径的记录，并在正向筛选后对故障去重；反向筛选排除存在符合口径记录的故障。

不依赖 `OtnFaultListView` 的数量注解，以便相同 FilterSet 在列表页、REST API 等调用场景中保持可用。

## 表单设计

在 `OtnFaultFilterForm` 增加可空布尔字段：

- 标签：“造成裸纤业务中断”；
- 控件：与现有布尔筛选一致的“--------- / 是 / 否”下拉框；
- 字段顺序：紧跟 `fault_occurrence_time_before`，位于 `dispatch_time` 之前。

## 测试

先增加失败测试，再实现功能。测试覆盖：

- FilterSet 暴露新字段并使用裸纤、中断两个条件；
- 选择“是”仅保留中断数量大于 0 的故障；
- 选择“否”仅保留中断数量等于 0 的故障；
- 多条匹配影响记录不会产生重复故障；
- 表单标签及字段顺序符合要求。

本次不修改模型、数据库结构、故障列表数量展示或裸纤业务统计口径。
