# 光缆中断计划整改故障排除设计

## 目标

故障统计模块的“光缆中断情况”不再统计一级原因为“光缆整改”且二级原因为“计划报备”的故障。该组合沿用原“割接排除”统计口径。

## 排除规则

仅在以下两个条件同时成立时排除故障：

- `interruption_reason == "cable_rectification"`（光缆整改）
- `interruption_reason_detail == "planned_reporting"`（计划报备）

只满足其中一个条件的故障继续纳入统计。排除规则不改变挂起故障等其他既有统计条件。

## 覆盖范围

统一排除规则适用于“光缆中断情况”的全部数据入口：

- 顶部统计指标
- 原因、光缆属性、历时等图表
- 重复中断统计
- 指标和图表的下钻故障明细
- 分公司光缆中断统计
- 定位地图中的故障点
- “故障和异常事件（按影响程度划分等级）”区域：
  - 光缆中断、供电故障、空调与设备故障等级占比
  - 故障等级与事件汇总（总次数及 I 至 V 类）
  - 当前期、环比和同比统计
  - 等级卡片与环形图点击后的下钻明细

其他故障统计模块不受影响。

## 实现设计

在 `netbox_otnfaults/statistics_views.py` 中定义可复用的 ORM 排除条件，并由光缆中断统一基础查询 `get_cable_break_base_queryset()` 应用。对于尚未直接复用该基础查询的光缆中断入口，例如下钻明细范围和物理每日图查询，调用同一排除规则，避免复制字段组合或产生统计口径偏差。

地图、分公司统计及主要光缆中断指标继续通过统一基础查询获得数据，不在各消费者内重复过滤。

影响程度等级区域不修改全局 `Q_CLASS_*` 条件，而是在当前期和对比周期进入等级注解与聚合前应用同一个排除函数。环形图遍历过滤后的注解查询集。下钻明细在收到 `impact_level` 或 `fault_group` 条件时应用相同排除函数，保证卡片、环形图与明细一致。“割接实施”统计来自 `CutoverTask`，不应用故障原因过滤。

## 数据流

原始故障查询先应用时间范围、光缆中断类型和非挂起条件，再排除“光缆整改 + 计划报备”组合。过滤后的查询集流向指标聚合、图表、重复故障检测、分公司统计和地图。下钻明细在应用光缆中断作用域时使用相同排除条件，保证明细行数和聚合指标一致。

影响程度等级区域的当前期与对比周期查询在等级注解前排除同一组合，过滤后的数据同时流向等级汇总和三张环形图。等级或环形图下钻请求也在应用等级、故障分组条件前排除该组合。

## 测试设计

先增加失败回归测试，再修改生产代码：

1. 锁定统一基础查询包含组合条件排除规则。
2. 锁定下钻明细和未复用基础查询的光缆中断入口应用同一规则。
3. 验证排除使用组合语义，不能将所有“光缆整改”或所有“计划报备”故障单独排除。
4. 锁定当前期与对比周期等级查询均先应用统一排除函数。
5. 锁定等级卡片及环形图下钻明细应用相同规则。
6. 运行光缆中断统计相关测试及 Python 编译检查。

## 非目标

- 不修改数据库模型或生成迁移。
- 不改变故障录入、详情页或普通故障列表的展示。
- 不改变截图所示影响程度等级区域之外的业务故障、供电、空调、设备等其他统计口径。
