# 态势大屏割接位置修正设计

## 背景

态势大屏的故障数据通过统一坐标解析器生成 `lat`、`lng`，割接数据则没有返回这两个字段。前端因此始终退化为按 `site_a` 名称查找 A 端站点坐标，导致割接自身经纬度和 A/Z 路径中点均被忽略。

## 目标

使态势大屏中的割接位置与故障位置遵循同一套坐标解析规则：

1. 优先使用割接自身的 `cutover_latitude`、`cutover_longitude`。
2. 未填写显式坐标且只有一个 Z 端时，使用 A/Z 光缆路径中点。
3. 无可用路径时使用 A 端站点坐标。
4. A 端无坐标时使用所有有效 A/Z 站点的平均中心。
5. 无法解析坐标时不生成地图标记。

## 方案

在 `DashboardDataAPI` 组装割接数据时调用已有的
`resolve_cutover_coordinates()`。只有解析成功的割接才写入地图所需的
`lat`、`lng`，同时返回 `site_a_id`、`site_z_ids`，使割接事件聚焦时能够复用故障站点聚焦逻辑。

前端继续消费 `c.lat`、`c.lng`。现有按 A 端名称匹配的兼容回退暂时保留，以兼容缓存或旧接口响应；新接口响应不再依赖该回退。

## 范围

- 修改态势大屏数据接口的割接序列化逻辑。
- 补充态势大屏割接坐标的回归测试。
- 不修改统一坐标解析器的既有优先级。
- 不修改一张图、割接详情页或数据库结构。

## 测试

回归测试应确认：

- 态势大屏导入并调用 `resolve_cutover_coordinates()`。
- 解析成功后割接数据包含 `lat`、`lng`。
- 割接数据包含 `site_a_id`、`site_z_ids`。
- 无法解析坐标的割接不会生成错误地图位置。
- 现有故障坐标和态势大屏测试继续通过。
