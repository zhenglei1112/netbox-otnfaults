# 割接已完成状态必填校验设计

## 目标

当割接任务状态修改为“已完成”时，要求以下字段全部填写：

- 割接开始时间（`started_at`）
- 割接完成时间（`completed_at`）
- 割接封包时间（`closed_at`）
- 割接是否超时（`is_timeout`）
- 割接效果（`cutover_result`）
- 是否整改（`rectification_status`）

其他状态不触发这组条件必填校验。

## 校验设计

在 `CutoverTaskForm.clean()` 中执行服务端条件校验。状态为 `CutoverStatusChoices.COMPLETED` 时，遍历上述六个字段，并使用 `add_error()` 将同一条错误信息绑定到每个缺失字段：

> 状态为已完成时，此字段必填。

校验一次检查全部字段，因此单次提交会同时显示所有缺失项，并阻止无效数据保存。模型字段及数据库约束保持不变，不需要迁移。

## 页面交互

错误仅显示在对应字段下方，不显示页面顶部的表单错误汇总。

编辑页收到无效表单后，按页面字段顺序查找第一个缺失字段：

1. 割接开始时间
2. 割接完成时间
3. 割接封包时间
4. 割接是否超时
5. 割接效果
6. 是否整改

页面加载完成后平滑滚动至该字段，并将焦点放到对应原生控件或 TomSelect 控件。其余缺失字段仍同时保留字段级错误提示。

## 错误处理边界

- 仅隐藏顶部错误汇总，不隐藏字段级错误。
- 非本规则产生的字段错误仍应显示在其字段下方。
- 表单级非字段错误不在本需求范围内，不改变其现有处理方式。
- 前端滚动仅改善定位体验；是否允许保存始终由服务端校验决定。

## 测试

增加定向回归测试，覆盖：

- 状态为“已完成”且六个字段均为空时，六个字段同时产生错误。
- 状态为“已完成”且只缺部分字段时，仅缺失字段产生错误。
- 状态为“已完成”且六个字段齐全时，不产生该规则错误。
- 状态不是“已完成”时，不触发该规则。
- 编辑模板不渲染顶部汇总，并包含滚动、聚焦第一个缺失字段的逻辑。
