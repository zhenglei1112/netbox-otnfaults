# 割接列表列设置补全设计

## 目标

让 `CutoverTask` 自身定义的全部业务字段都能出现在割接列表的“列设置”中。现有默认列保持不变，用户只有主动选择后才会显示新增列。

## 范围

- 在 `CutoverTaskTable` 中补充目前遗漏的 31 个业务字段，包括 A/Z 端站点。
- 关系字段使用可链接的普通列或多对多列。
- 枚举字段使用 `ChoiceFieldColumn`，并为 CSV 导出返回显示名称。
- 日期时间字段统一使用当前割接列表的分钟级格式。
- 数组、JSON 和文本字段提供稳定、可读的列表及 CSV 输出。
- `actions` 始终保留为最后一列。
- 不修改 `default_columns`，不改变列表初始展示。

## 字段分组

- 登记与计划：登记人、计划割接时间记录、预计影响时长。
- 位置：A端站点、Z端站点、经度、纬度。
- 资源信息：割接原因、光纤来源、光缆路由属性、资源所有者、维护方式、代维方/租赁方、代维/租赁合同。
- 组织联系人：割接管理单位名称、割接联系人电话。
- 实施与闭环：客户审核明细、开始时间、完成时间、封包时间、超时原因、遗留问题。
- 整改信息：是否整改、整改措施、措施描述、整改主体、整改进度、计划完成时间、实际完成时间、整改完成情况描述。
- 其他：评论。

## 实现方式

1. 先增加源码级回归测试，验证模型业务字段均包含在 `CutoverTaskTable.Meta.fields` 中、`actions` 位于最后、默认列未被扩展。
2. 在 `CutoverTaskTable` 声明需要定制行为的关系、枚举、时间和多值列。
3. 将全部遗漏字段加入 `Meta.fields`，按编辑表单的业务顺序组织。
4. 为枚举及多值列补充 CSV 友好的 `value_*` 方法。

## 验证

- 回归测试在修改表格前因遗漏字段而失败。
- 修改后目标测试通过。
- 运行割接管理相关测试，确认现有列表结构和脚手架约束未被破坏。
- 运行 Python 编译检查。

## 不包含

- 不修改模型、迁移、表单、过滤器或 API。
- 不改变默认显示列、排序、分页或筛选行为。
- 不增加新的数据库查询流程。
