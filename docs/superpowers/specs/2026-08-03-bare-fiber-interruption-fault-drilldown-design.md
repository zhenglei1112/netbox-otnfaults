# 裸纤业务中断故障明细下钻设计

## 目标

在故障统计模块中，点击“裸纤业务中断情况”的四张指标卡片后，下方故障明细仅展示导致当前统计周期内裸纤业务中断的关联故障。故障明细按故障记录去重，同一故障影响多条裸纤业务时只展示一行。

## 当前问题

四张卡片已经带有可点击样式，但没有配置下钻筛选参数。现有故障明细接口只支持按故障自身字段筛选，不能依据 `OtnFaultImpact` 裸纤业务影响关系筛选，因此点击卡片不会得到对应故障列表。

## 统计与明细口径

卡片继续按裸纤业务影响记录统计：

- 总起数：符合条件的裸纤业务影响记录数。
- 去除同源起数：符合条件的影响记录关联的不同故障数。
- 总历时：各条符合条件的裸纤业务中断历时之和。
- 去除同源历时：每个关联故障取其最长一条裸纤业务中断历时后求和。

明细表按故障记录展示。所有卡片均下钻到同一组关联故障，并按 `OtnFault.id` 去重。因此总起数可以大于明细行数，总历时也不要求等于明细表中故障历时之和。

## 有效裸纤业务中断条件

下钻必须与卡片统计使用相同条件：

- `service_type` 为裸纤业务；
- 业务中断时间位于当前统计周期；
- `business_impact` 不是“未中断”；
- 关联故障不是挂起故障；
- 排除“光缆整改 + 计划上报 + 协调通过”的影响记录；
- 应用当前物理故障省份范围；
- 子公司页额外应用现有子公司故障范围和排除规则。

统计周期以业务影响记录的 `service_interruption_time` 为准。关联故障本身的发生时间可以早于统计周期，只要裸纤业务中断发生在当前周期内，仍应出现在下钻明细中。

## 交互设计

四张卡片配置统一的“裸纤业务中断”下钻范围。点击任一卡片时：

1. 清除之前的物理故障下钻条件；
2. 激活裸纤业务中断范围；
3. 滚动到下方故障明细；
4. 请求并展示关联故障列表；
5. 在明细筛选提示中显示“裸纤业务中断”。

清除筛选后恢复当前统计周期内的完整故障明细。子公司页的同类卡片使用相同下钻口径，并继续展示在子公司范围内的故障明细。

## 后端设计

将“有效裸纤业务中断影响记录”的筛选提取为可复用查询逻辑，供卡片统计和故障明细下钻共同使用，避免两处口径漂移。

故障明细接口识别新的裸纤业务中断范围后：

1. 按当前周期、省份和页面范围取得有效影响记录；
2. 提取非空的关联故障 ID；
3. 使用这些 ID 筛选 `OtnFault`；
4. 继续沿用现有排序、重复标记和结果序列化逻辑。

裸纤业务中断范围不使用故障发生时间作为前置周期限制，因为卡片周期由业务中断时间决定。

## 前端设计

复用现有指标卡片事件委托和明细加载流程，不新增页面组件。渲染裸纤业务中断数据时，为四张卡片写入统一的下钻范围、显示标签和指标类型。物理故障页调用现有故障明细加载函数；子公司页调用现有子公司故障明细加载函数。

## 测试与验收

- 回归测试证明四张卡片都携带裸纤业务中断下钻参数。
- 后端测试证明明细接口使用与卡片一致的裸纤影响筛选条件。
- 后端测试覆盖一条故障影响多条裸纤业务时只返回一条故障明细。
- 后端测试覆盖故障发生在周期前、业务中断发生在周期内时仍返回该故障。
- 后端测试覆盖未中断业务、挂起故障以及已协调通过的计划性光缆整改被排除。
- 子公司范围测试证明原有省份和维护单位排除规则继续生效。
- 运行相关测试文件及 Python 编译检查，确认没有回归后再报告完成。

## 非目标

- 不修改四张卡片的统计公式或显示文案。
- 不把业务影响记录拆成多行显示在故障明细中。
- 不新增数据库字段、迁移或独立明细接口。
- 不修改 NetBox 核心目录。
