# 外购合同关联故障“割接”列设计

## 目标

在外购合同详情页下方的“关联故障”精简列表中增加“割接”列，帮助用户快速识别由已计划割接造成的故障。

## 展示规则

- 关联故障列表最终列顺序为：故障编号、值守人员、故障起始时间、故障历时、故障分类、割接、故障位置A端站点、故障位置Z端站点、紧急程度、处理状态、标签。
- 删除 ID 和处理进度列；ID 不再作为可配置列提供，避免用户历史列偏好将其重新显示。
- “故障位置A端站点”为单对象链接列，“故障位置Z端站点”为多对象链接列。
- 当故障的一级原因内部值为 `cable_rectification`（光缆整改），且二级原因内部值为 `planned_reporting`（计划报备）时，显示绿色对勾。
- 其他任何组合以及原因缺失时，单元格留空。
- 新列不参与排序。

## 实现范围

修改 `ContractOtnFaultTable` 的可用字段、默认字段及顺序：移除 `pk` 与 `progress`，加入 `interruption_location_a` 与 `interruption_location`。割接标记继续由表格渲染方法根据当前故障记录计算。

关联故障查询对 A 端站点使用 `select_related('interruption_location_a')`，对 Z 端站点使用 `prefetch_related('interruption_location')`，避免渲染新增列时产生逐行额外查询。通用故障列表、故障模型和数据库结构不变。

## 测试

先新增失败测试，验证最终可用列与默认列顺序完全一致、`pk` 和 `progress` 已移除、A/Z 端字段使用正确的链接列类型，并验证查询预加载。割接列测试继续覆盖以下渲染行为：

1. 光缆整改 + 计划报备：输出绿色对勾。
2. 光缆整改 + 非报备：输出空内容。
3. 其他一级原因 + 计划报备：输出空内容。
