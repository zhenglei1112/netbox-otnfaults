# PRD: 割接模型与故障模型地图坐标估算统一需求文档

## 1. 概述
在 Netbox OTN 插件中，割接模型（CutoverTask）和故障模型（OtnFault）均关联了 A 端站点（`interruption_location_a`）和 Z 端站点（`interruption_location`）。
当用户未填报具体的定位经纬度时，系统需要对事件发生/实施的位置进行智能估算并在地图中定位。

目前故障模型已具备成熟的多级估算机制（显式坐标 -> 光缆路径中点 -> A端站点 -> A/Z平均中心），而割接模型仅具备简易的算术平均中心估算。本需求旨在将割接估算逻辑统一到故障模型的估算逻辑，并收敛为一套可复用的后端服务代码。

## 2. 详细需求

### 2.1 坐标估算优先级规则
对于 `CutoverTask` 和 `OtnFault`，估算坐标应严格遵循以下优先级：
1. **显式经纬度**：若对象本身填报了经纬度（Cutover: `cutover_latitude`/`longitude`；Fault: `interruption_latitude`/`longitude`），直接使用。
2. **光缆路径几何中点**：若无显式经纬度，且配置了 A 端站点和 1 个 Z 端站点，自动检索两站点之间包含 `geometry` 矢量数据的光缆路径（`OtnPath`），取路径几何图形的中点坐标。
3. **A 端站点坐标**：若无对应光缆路径或存在多个 Z 端站点，优先使用 A 端站点的坐标。
4. **站点算术平均中心**：若 A 端站点无坐标，计算所有配置了坐标的 A 端与 Z 端站点的经纬度算术平均值。
5. **系统默认坐标**：若均无坐标，使用插件配置的默认地图中心点。

### 2.2 重构要求
- 后端服务 `netbox_otnfaults/services/fault_coordinates.py` 重构为通用坐标解析器。
- `LocationMapView` 支持 `cutover` 参数解析。
- `cutovertask.html` 地图按钮追加 `cutover` 参数。
- 向后兼容 `OtnFault` 的原有坐标解析逻辑。
