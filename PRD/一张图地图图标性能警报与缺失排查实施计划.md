# 一张图地图图标性能警报与缺失排查实施计划

此实施计划旨在解决地图渲染过程中，由于自定义图标在初次加载时异步加载较慢，以及底图样式切换导致已注册图标被清空后，MapLibre GL 在帧渲染循环中不断渲染“错误纹理”引起的 `performance warning: READ-usage buffer was written, then fenced...` 警报问题。

## 核心原因分析

1. **异步加载导致的短暂缺失**：在 `init` 阶段，图层被设置为 `visible` 时，`_loadFaultIcons` 中的异步图标加载（通过 SVG Blob -> Image -> Canvas，耗时约 1.3 秒）尚未完成。此时地图图层引用了尚不存在的图标，导致前 1.3 秒的每一帧渲染都会报 `_renderErrorTexture` 警报。
2. **底图/样式切换后图标清空**：在用户切换地图样式或白天/黑夜模式时，底图 Style 被重新应用，这会清空以前通过 `map.addImage` 注册的所有自定义图片。由于没有重新加载图标的机制，后续图层渲染将永久找不到图标，从而无限在控制台报 WebGL 警报，导致严重的页面卡顿与内存损耗。

## 解决设计方案

在 `fault_mode.js` 中引入 MapLibre 的 `styleimagemissing` 事件监听器：
- 当图层在渲染时发现任何图标不存在，MapLibre 会触发该事件。
- **割接卡片图标（`cutover-card-${id}-${status_key}`）**：由于其绘制完全基于 Canvas 2D，是纯同步过程，我们可以根据事件中的 ID 直接在监听器中同步绘制并使用 `map.addImage` 注册，实现 100% 同步且无缝的渲染。
- **故障点标记图标（`fault-marker-${category}-${status}` 或 `fault-marker`）**：我们根据 ID 解析出故障类型与状态，通过本地 SVG 库生成彩色图标，异步添加进地图中。
- 此项优化由于完全实现了“按需动态生成图标”和“丢失自动补齐”，不仅解决性能警报，更能将初始加载图标的耗时从 1.3秒 降低到几乎为 0，大大提升首次加载速度。

## 修改方案

### 一张图模式插件前端代码

#### [MODIFY] [fault_mode.js](file:///d:/Src/netbox-otnfaults/netbox_otnfaults/static/netbox_otnfaults/js/modes/fault_mode.js)

1. 在 `_setupEventListeners` 中，添加对地图 `styleimagemissing` 事件的监听。
2. 实现 `styleimagemissing` 的事件回调函数：
   - 匹配并处理割接卡片图标 `cutover-card-${id}-${status_key}`。
   - 匹配并处理故障标记图标 `fault-marker-${category}-${status}` 和 `fault-marker`。
3. 确保提取属性时的容错性，即使数据尚未拉取完毕，也能依据 ID 中携带的状态信息正常绘制底图图标，避免崩溃。

具体代码改动思路如下：

```javascript
    // 监听缺失图标事件，动态自动补齐
    map.on("styleimagemissing", (e) => {
      const id = e.id;
      
      // 1. 处理割接卡片图标
      if (id.startsWith("cutover-card-")) {
        const matches = id.match(/^cutover-card-(\d+)-(.*)$/);
        if (matches) {
          const cutoverId = matches[1];
          const statusKey = matches[2];
          
          // 从本地缓存数据中查找该割接配置，若找不到则退化到默认配置
          const item = (this.cutoverData || []).find(c => String(c.id) === String(cutoverId)) || {
            id: cutoverId,
            status_key: statusKey
          };
          
          try {
            const canvasData = this._createCutoverCardIcon(item);
            if (!map.hasImage(id)) {
              map.addImage(id, canvasData, { pixelRatio: 2 });
            }
          } catch (err) {
            console.error("动态注册割接卡片图标失败:", err);
          }
        }
      }
      
      // 2. 处理故障点图标
      if (id === "fault-marker" || id.startsWith("fault-marker-")) {
        let category = "other";
        let status = "processing";
        
        if (id.startsWith("fault-marker-")) {
          const matches = id.match(/^fault-marker-(.*)-(.*)$/);
          if (matches) {
            category = matches[1];
            status = matches[2];
          }
        }
        
        const statusColors = {
          'processing': '#dc3545',
          'temporary_recovery': '#0d6efd',
          'suspended': '#ffc107',
          'closed': '#198754'
        };
        const color = statusColors[status] || statusColors['processing'];
        const svgContent = (window.FAULT_SVG_ICONS && window.FAULT_SVG_ICONS[category]) || 
                           (window.FAULT_SVG_ICONS && window.FAULT_SVG_ICONS.other) || 
                           '<svg viewBox="0 0 32 32"><circle cx="16" cy="16" r="4" fill="white"/></svg>';
        
        this._createColoredIconPromise(svgContent, color).then(result => {
          if (!map.hasImage(id)) {
            map.addImage(id, result.imageData, { pixelRatio: 2 });
          }
        }).catch(err => {
          console.error("动态注册故障图标失败:", id, err);
        });
      }
    });
```

为了方便复用，我们将 `_loadFaultIcons` 内部的单图标生成逻辑提取为 `this._createColoredIconPromise(svgContent, bgColor)` 方法。

## 验证计划

### 手动验证
- 一张图模块加载时，观察控制台。
- 确认不再输出 `performance warning: READ-usage buffer was written...` 性能警告。
- 检查故障标记图标和割接卡片是否能正常、美观地呈现在地图上。
- 切换地图样式（底图底色），确认在样式切换后，自定义图标会自动触发 `styleimagemissing` 重新注册，完全不报任何警报，且图标位置及显示不受底图切换的影响。
